## 5. Implementation Details

### 5.1 Frontend Dockerfile (`frontend/Dockerfile`)

**Multi-stage build approach:**

- **Stage 1 (Build):** Uses `node:20-alpine` to install dependencies and build the React/Vite application (`npm run build`).
- **Stage 2 (Runtime):** Uses `nginx:alpine` to serve the production build. A custom `nginx.conf` proxies `/api/` and `/health` requests to the backend service.
- Exposes port `80`.
- Includes a Docker `HEALTHCHECK` using `wget` to verify Nginx is responding.

```dockerfile
# ---- Build stage: compile the React application ----
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json ./
RUN npm install
COPY . .
RUN npm run build

# ---- Runtime stage: serve the production build with Nginx ----
FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
# hadolint ignore=DL3025
HEALTHCHECK --interval=15s --timeout=5s --retries=5 --start-period=10s \
  CMD wget -qO- http://127.0.0.1:80/ >/dev/null || exit 1
CMD ["nginx", "-g", "daemon off;"]
```

### 5.2 Backend Dockerfile (`backend/Dockerfile`)

**Multi-stage build approach:**

- **Stage 1 (Dependencies):** Uses `node:20-alpine` to install only production dependencies (`--omit=dev`), then cleans npm cache.
- **Stage 2 (Runtime):** Uses `node:20-alpine`, copies dependencies from the first stage, copies application source, runs as non-root `node` user for security.
- Sets `NODE_ENV=production` and `PORT=3000`.
- Includes a Docker `HEALTHCHECK` hitting the `/health` endpoint.

```dockerfile
# ---- Build stage: install production dependencies ----
FROM node:20-alpine AS deps
WORKDIR /app
COPY package.json ./
RUN npm install --omit=dev && npm cache clean --force

# ---- Runtime stage ----
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production \
    PORT=3000
COPY --from=deps /app/node_modules ./node_modules
COPY . .
EXPOSE 3000
# hadolint ignore=DL3066
USER node
# hadolint ignore=DL3025
HEALTHCHECK --interval=15s --timeout=5s --retries=5 --start-period=20s \
  CMD wget -qO- http://127.0.0.1:3000/health || exit 1
CMD ["node", "src/server.js"]
```

### 5.3 Docker Compose for Local Development (`docker-compose.yml`)

Orchestrates all 4 services with local builds:

| Service    | Image / Build           | Port Mapping | Health Check |
|------------|------------------------|--------------|--------------|
| frontend   | `build: ./frontend`    | 8080:80      | Dockerfile HEALTHCHECK |
| backend    | `build: ./backend`     | 3000:3000    | Dockerfile HEALTHCHECK |
| postgres   | `postgres:16-alpine`   | 5432:5432    | `pg_isready` |
| redis      | `redis:7-alpine`       | 6379:6379    | `redis-cli ping` |

**Key configurations:**

- PostgreSQL data persisted via named volume `pgdata`
- Database schema initialized via `./backend/db/init.sql` mounted to `/docker-entrypoint-initdb.d/`
- Service dependencies with `condition: service_healthy` ensuring startup order
- Environment variables passed via `.env` file (secrets not hardcoded)

### 5.5 Nginx Reverse Proxy Configuration (`frontend/nginx.conf`)

```nginx
server {
  listen 80;
  server_name _;
  root /usr/share/nginx/html;
  index index.html;

  location /api/ {
    proxy_pass http://backend:3000/api/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location /health {
    proxy_pass http://backend:3000/health;
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

### 5.6 Database Schema (`backend/db/init.sql`)

```sql
CREATE TABLE IF NOT EXISTS users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS tasks (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  status VARCHAR(20) NOT NULL DEFAULT 'Pending'
    CHECK (status IN ('Pending', 'In Progress', 'Completed')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_tasks_user_id ON tasks(user_id);
```

## 10. Fixes Applied During Implementation

### Fix 1: Database Schema Initialization in Deploy Compose

**Problem:** `docker-compose.deploy.yml` was missing the PostgreSQL init script volume mount, causing the database to start without tables.

**Fix:** Added the volume mount:
```yaml
volumes:
  - pgdata:/var/lib/postgresql/data
  - ./backend/db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```

### Fix 2: Jest ESM Transform Configuration

**Problem:** Jest tests failed with ESM import errors.

**Fix:** Added `transform: {}` to `tests/jest.config.js` to disable Babel transform for native ESM modules.

### Fix 3: Hadolint Dockerfile Compliance

**Problem:** Hadolint flagged `DL3025` (HEALTHCHECK CMD notation) and `DL3066` (non-numeric USER) causing CI failures.

**Fix:** Added `# hadolint ignore=DL3025` and `# hadolint ignore=DL3066` comments to suppress non-critical warnings.

### Fix 4: Frontend Healthcheck IP

**Problem:** Frontend Dockerfile HEALTHCHECK used `localhost` which may not resolve inside Alpine containers.

**Fix:** Changed to `127.0.0.1` for reliable health checks.
